# World Intelligent 相机自动识别与裁剪设计

## 目标

在现有 RK3588 无界面双目标定平台中自动识别新接入的 DECXIN 双目相机。只有设备名称、分辨率和左侧码带三项条件同时满足时，系统才设置 `world intelligent` 标签并调用专用裁剪；昨天使用的普通 SBS 相机行为保持不变。

## 识别条件

系统读取 V4L2 设备名称并检查首个有效视频帧。以下条件必须全部成立：

1. V4L2 设备名称包含 `DECXIN Camera`，忽略大小写。
2. 原始帧尺寸严格等于 `4000×1200`。
3. 原始帧左侧 `160` 像素符合码带特征：该区域的暗像素比例至少为 `0.35`，并且比紧邻的 `160` 像素图像区域至少高 `0.25`。

只有三项全部通过时，设备标签为 `world intelligent`。名称或尺寸符合但码带验证失败时，系统不得猜测布局或执行专用裁剪，而是进入错误状态并明确提示码带识别失败。

## 图像布局与数据流

`world intelligent` 原始帧布局固定为：

```text
[0:160]       码带
[160:2080]    左眼，1920×1200
[2080:4000]   右眼，1920×1200
```

系统保留原始 `4000×1200` SBS 帧用于追溯。自动检测、手动采集、自动采集、预览和求解统一使用裁剪后的左右 `1920×1200` 图像。禁止对标定输入进行缩放、增强或插值。

普通 SBS 相机继续走现有等宽分割逻辑。两类相机通过统一的设备配置结果向采集引擎提供标签、模式、单眼尺寸和分割策略，避免在采集循环中散落型号判断。

## 模式选择

RK3588 启动时依次探测受支持模式：

1. `MJPG 4000×1200@30`，用于 `world intelligent` 候选相机。
2. `MJPG 3840×1080@30`，用于昨天的平台和普通 SBS 相机。

成功打开后，以实际返回的帧尺寸为准进行配置识别。不得仅根据请求模式设置标签。

## 界面与状态

Web 状态接口和页面增加以下信息：

```text
设备标签：world intelligent
设备模式：MJPG 4000×1200@30
单眼分辨率：1920×1200
码带检测：通过（160 px）
```

普通相机显示原有模式，并将设备标签显示为 `generic stereo`、码带检测显示为“不适用”。

## 错误处理

- 找不到支持的分辨率：报告设备不支持平台规定的采集模式。
- `4000×1200` 且名称匹配，但码带条件不成立：报告 `world intelligent 码带识别失败`，不自动退回等分裁剪。
- 采集中帧尺寸改变：停止本轮采集并报告期望值与实际值。
- 裁剪结果不是两个 `1920×1200` 图像：停止采集，不保存该帧。

## 测试与验收

单元测试覆盖：

- 名称、分辨率、码带均匹配时返回 `world intelligent`。
- 三项条件分别不匹配时不设置该标签。
- 专用裁剪精确移除前 `160` 像素并输出两个 `1920×1200` 图像。
- `swap_eyes` 在专用裁剪后仍正确生效。
- `3840×1080` 普通 SBS 相机继续等分为两个 `1920×1080` 图像。
- 状态接口返回标签、模式、单眼分辨率和码带状态。

RK3588 实机验收使用当前 `/dev/video0`：确认设备名为 DECXIN、模式为 `4000×1200@30`、标签为 `world intelligent`，并验证左右眼各检测到 `8×5` 共 `40` 个棋盘角点。
