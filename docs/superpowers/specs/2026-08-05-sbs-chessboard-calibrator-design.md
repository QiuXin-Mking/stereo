# SBS 双目棋盘格标定工具设计

日期：2026-08-05  
状态：设计已批准，待实现计划  
目标设备：macOS AVFoundation 中名称为 `UVC Camera 1` 的单设备 SBS 双目相机

## 1. 目标

从零实现一套独立的双目棋盘格标定工具。操作者通过一个入口完成设备识别、最高原生模式选择、棋盘参数确认、引导式自动采集、标定求解、质量验收和工程文件导出。

工具服务于 OpenCV/C++。正式产物包括 OpenCV YAML、JSON、NumPy NPZ、C++ 可直接加载的校正映射，以及最小加载示例。工具不得依赖或复用工作区现有的 `stereo_calib_kit/`。

## 2. 已确认范围

- 相机形态：一个 UVC 设备输出左右拼接的 SBS 帧。
- 平台：第一版以 macOS 和 AVFoundation 为目标。
- 图像模式：选择设备支持的最高原生分辨率；同分辨率下选择可稳定运行的最高帧率。
- 标定板：A4 横向、9×6 内角点、10×7 方格、标称方格边长 20 mm。
- 采集方式：引导式自动采集，不要求操作者按键拍照。
- 相机模型：默认 OpenCV pinhole 模型和 5 参数畸变模型。
- 输出用途：OpenCV/Python 和 OpenCV/C++。
- 不在第一版范围：两个独立 UVC 设备、上下拼接、ROS/Kalibr、嵌入式私有二进制、在线深度算法调参、鱼眼模型求解。

若预览表现出明显鱼眼特征，工具应停止并提示切换到未来的 fisheye 配置，不得静默使用 pinhole 模型。

## 3. 操作入口

操作者在新目录中运行一个入口：

```bash
./calibrate
```

入口顺序执行七个阶段：

1. 按设备名寻找 `UVC Camera 1`，每次启动重新解析 AVFoundation 数字索引。
2. 枚举视频格式，按像素面积选择最高原生分辨率；同分辨率按帧率降序尝试，并用连续采帧验证稳定性。
3. 验证 SBS 帧宽可被 2 整除，显示左右眼预览，让操作者确认左右顺序。
4. 显示 9×6 棋盘参数，要求输入打印后实测方格边长；可选输入左右镜头光心间距的粗测值。
5. 进入引导采集窗口，自动采集足够且有差异的样本。
6. 自动求解、清理离群样本、重新求解并验收。
7. 通过时导出正式结果；不通过时保留好样本并进入定向补拍。

每次运行创建独立 session。中途中断后再次运行时，入口应提供继续最近 session 或新建 session 的选择。

## 5. 设备探测与原始图像约束

设备探测以名称为主键，数字索引只作为本次 session 的解析结果写入 `session.yaml`。这避免 macOS 在设备插拔后改变 `[0]`、`[1]` 的含义。

格式选择规则如下：

1. 使用 AVFoundation/FFmpeg 枚举设备和可用格式。
2. 对候选格式按 `width × height` 降序，同像素面积按帧率降序排列。
3. 每个候选模式连续读取一段样本，拒绝打不开、尺寸不符、持续丢帧或帧时间明显不稳定的模式。
4. 选取第一个稳定模式，并把完整 SBS 分辨率、单眼分辨率、像素格式、请求帧率和实测帧率写入 session。

标定检测和保存必须使用未缩放的原始图像。界面可以为显示而缩放，但不得把预览尺寸用于求解。SBS 拆分位置固定为 `frame_width / 2`，左右高度必须一致。操作者在开始采集前通过预览确认左半幅对应左眼；若相反，可在本 session 中启用 `swap_eyes`，且该信息写入全部产物。

## 6. 棋盘标定板

工具附带 A4 横向 1:1 PDF 和 SVG：

- 9×6 内角点，即 10×7 个方格。
- 标称方格边长 20 mm，棋盘主体为 200×140 mm。
- 页面包含 100 mm 校验尺、打印方向和“实际大小/100%，禁止适应页面”提示。
- 棋盘外围保留足够白边，避免纸张边缘干扰角点检测。

标称尺寸只用于制板。首次采集前，操作者必须用尺测量打印后的实际方格边长并输入毫米值。工具将该数值转换为米参与三维目标点构造，并同时在结果中保存 `square_size_mm` 和 `length_unit: meter`。

## 7. 引导式自动采集

### 7.1 窗口布局

顶部显示设备名、完整 SBS 模式、单眼分辨率、实际帧率和已接收样本数。中部并排显示左右眼：

- 棋盘角点覆盖层。
- 当前希望棋盘到达的目标区域。
- 左右眼检测成功状态。
- 预览缩放提示。

下部显示当前唯一动作建议、五类质量状态、0.8 秒稳定倒计时和覆盖矩阵。底部提供：

- `P`：暂停或继续。
- `U`：撤销最近接收的一对。
- `Q`：保存当前 session 并退出。

第一版不提供“强制接收”按键，避免坏样本进入正式求解。

### 7.2 下一最佳姿态

引导器根据已接收角点计算以下特征：

- 棋盘中心在归一化画面中的位置。
- 棋盘投影面积，即近、中、远三种尺度覆盖。
- 由棋盘单应性或 PnP 估计的水平和垂直倾角。
- 左右眼共同可见性和边缘余量。

系统维护位置、尺度和倾角覆盖状态，优先提示缺口最大的姿态。提示必须是单一、可执行的中文动作，例如“移到右下区域，保持中等距离，并向左倾斜”。

目标采集 32 对。若 24 对后所有覆盖要求均满足，可以提前结束；若覆盖仍不足，最多引导至 40 对。达到 40 对仍不满足时，保存 session 并明确列出缺少的姿态，不以低质量结果冒充成功。

### 7.3 自动接收门槛

只有以下条件同时成立且连续稳定 0.8 秒，才自动接收：

- 左右眼均完整检测到 9×6 内角点，并完成亚像素优化。
- 图像清晰度达到配置门槛。
- 黑白区域没有严重过曝或欠曝。
- 棋盘角点包围框与图像边缘保持安全余量。
- 棋盘在稳定窗口内没有明显快速移动。
- 当前样本相对历史样本提供足够新的位置、尺度或倾角信息。

界面一次只显示最主要的拒绝原因，例如“右眼棋盘不完整”“图像模糊”“移动过快”或“与样本 017 过于相似”。普通操作者不在界面中调整质量阈值；高级参数集中在 `configs/default.yaml`，并完整复制到 session。

每次接收保存：完整原始 SBS 帧、拆分后的左右图、亚像素角点、时间戳、姿态特征、全部质量指标和接收原因。默认不保存每一帧被拒图像，只记录拒绝原因计数；诊断配置可启用有限数量的拒绝样本保存，避免磁盘无界增长。

## 8. 求解

默认求解步骤：

1. 使用相同世界棋盘点分别标定左右眼内参和畸变。
2. 固定已求得内参，求解双目 `R`、`T`、`E` 和 `F`。
3. 计算每一图像对的单目重投影误差和校正后纵向极线误差。
4. 迭代移除误差显著偏离总体分布的图像对；每轮只移除最差样本并重新求解。
5. 离群移除上限为原接收样本的 20%，且最终有效样本不得少于 20 对。
6. 使用最终参数计算 `R1`、`R2`、`P1`、`P2`、`Q` 和左右 remap。

离群阈值使用配置中的绝对上限与基于中位数/MAD 的鲁棒阈值共同判断。所有移除样本及其指标写入报告，禁止无记录地丢弃。

## 9. 验收与定向补拍

默认 PASS 条件全部满足才导出正式结果：

- 最终有效图像对不少于 20。
- 位置、近中远尺度和水平/垂直倾角覆盖均通过。
- 左右单目标定 RMS 分别不大于 0.7 px。
- 立体校正后纵向极线误差中位数不大于 0.35 px，P95 不大于 1.0 px。
- 焦距为正，主点处于合理图像范围，畸变系数为有限值，矩阵无 NaN/Inf。
- 估计基线为有限正值。
- 若操作者输入了粗测镜头中心距，估计基线与粗测值偏差不大于 10%。

验收不能只依据总体 RMS。工具同时生成校正前后对比图，并叠加多条水平极线供肉眼检查。

不通过时状态为 RETAKE。工具保留通过质量检查的历史样本，指出导致失败的指标和缺失覆盖，并进入只补缺失姿态的采集流程。例如：“保留 25 对，补拍右下区域大俯仰姿态 6 对”。失败 session 的中间矩阵保存在诊断目录，但不得写入 `results/final/`。

## 10. 导出契约

PASS 后 `results/final/` 固定包含：

- `stereo_calibration.yaml`：OpenCV `cv::FileStorage` 可直接读取；含 schema 版本、设备和分辨率元数据、单位、左右 `K`/`D`、`R`/`T`/`E`/`F`、`R1`/`R2`/`P1`/`P2`/`Q` 和质量摘要。
- `stereo_calibration.json`：与 YAML 语义一致的人可读交换格式；矩阵使用显式行列数和扁平数据，避免数组形状歧义。
- `stereo_calibration.npz`：供 Python/NumPy 使用，稳定键名与 YAML 字段一致。
- `rectify_maps.yml.gz`：供 C++ `cv::FileStorage` 加载的压缩定点映射，键为 `left_map1`、`left_map2`、`right_map1`、`right_map2`。
- `rectify_maps.npz`：供 Python 使用的同语义映射。
- `rectification_preview.png`：至少一组校正前后左右拼图和水平极线。
- `quality_report.json`：机器可读的样本、误差、剔除和 PASS 结论。
- `quality_report.html`：本地可打开的可视化报告，不依赖外部网络资源。

所有格式必须包含 `schema_version`。YAML、JSON 和 NPZ 的数值通过自动化测试逐项比对。C++ 示例 `examples/cpp/load_calibration.cpp` 必须演示 FileStorage 加载、尺寸校验、`cv::remap` 和失败返回。

## 11. 错误处理

- 找不到设备名：重新列出当前 AVFoundation 视频设备和索引，不猜测其他设备。
- macOS 无相机权限：给出“系统设置 → 隐私与安全性 → 相机”的明确操作提示。
- 最高模式不稳定：记录失败原因并降级到下一帧率；不得在同一分辨率失败一次后直接缩小分辨率。
- SBS 宽度为奇数或左右几何不一致：停止采集并报告输入格式错误。
- 角点长期检测不到：提示核对内角点数、打印比例、反光、距离和棋盘是否同时出现在双眼。
- 写盘失败或空间不足：立即暂停采集，保持内存中的当前状态，并避免产生半写入的正式文件。
- 求解产生非有限矩阵或退化结果：标记 RETAKE，不导出 final。
- 用户退出：原子写入 session 状态，下次允许继续。

## 12. 测试与验证

### 单元测试

- 设备候选模式排序和降级规则。
- SBS 左右拆分、奇数宽拒绝和 `swap_eyes`。
- 位置、尺度、倾角覆盖计算和下一姿态选择。
- 清晰度、曝光、边缘、稳定性和新颖度门控。
- 离群样本移除上限和最少 20 对保护。
- YAML/JSON/NPZ 字段、形状、单位和 schema 一致性。

### 合成与离线集成测试

- 使用已知内外参生成带噪棋盘角点，确认求解结果在设定容差内恢复真值。
- 注入模糊、重复、边缘截断和高误差样本，确认质量门控和离群清理生效。
- 使用固定录制的 SBS 样本集跑完整流程，避免自动测试依赖真实相机。

### 硬件验收

- 在 `UVC Camera 1` 最高原生模式下连续预览和采集。
- 完成一轮 24–40 对引导采集。
- 验证断点退出和继续。
- 用导出的 maps 对未参与采集的现场画面做实时 remap，检查水平极线。
- 构建并运行 C++ 示例，确认读取 YAML/maps 后的输出与 Python remap 像素一致。

## 13. 成功标准

一名不了解 OpenCV 标定细节的操作者能够按单窗口中文提示完成采集；工具对坏样本自动拒绝，对覆盖不足给出明确动作，对不可信结果拒绝导出 final。通过后的结果能被 Python 和 C++ 示例加载，并在同一单眼分辨率下产生一致的立体校正图像。
