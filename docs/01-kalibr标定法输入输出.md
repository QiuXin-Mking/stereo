# Kalibr 相机 + IMU 联合标定法（输入 / 输出 / 原理）

## 一句话定位

这是本项目（`stereo_chessboard_calibrator`）里区别于 OpenCV 棋盘模式的**第二条标定链路**：标定对象不再是「左右两个镜头之间的关系」，而是**相机和内置 IMU 之间的外参（旋转 + 平移）以及两者的时间偏移**。它只对带 IMU 码带的 `world intelligent` 相机（4000×1200，左 160px 码带）开放。

> 底层用的是 ETH Zürich ASL 的开源工具箱 **Kalibr**。本工程只负责**录制**双目视频与 IMU 数据，Kalibr 求解（打 rosbag、相机/IMU 联合优化）在外部流程完成，RK3588 主机不再运行 Kalibr Docker 容器。

---

## 一、输入（Input）

输入分「标定板」「视觉数据」「IMU 数据」三类：

### 1. 标定板（AprilTag 板）

| 项 | 值 |
|---|---|
| 类型 | `aprilgrid`（AprilTag 网格，**不是** OpenCV 模式用的 5×8 棋盘） |
| 排列 | 8 列 × 6 行 |
| tag 边长 | 20 mm（`tagSize: 0.020`） |
| 间距 | 边长 × 0.3（`tagSpacing: 0.30`） |

对应外部 Kalibr 流程准备的 `target.yaml`（本工程不再生成标定板配置）。

### 2. 视觉数据（双目视频）

录制时以相机原生帧率把左右眼分别写为视频（不抽帧）：

- `cam0.avi` — 左眼灰度视频（1920×1200，不含 160px 码带）
- `cam1.avi` — 右眼灰度视频（1920×1200，不含码带）
- 编码为 MJPEG（帧内编码）；后续由外部流程解帧供 Kalibr 使用

### 3. IMU 数据

- `imu_decoder.py` 从画面左侧 160px 码带里解码出 IMU 样本，写 `imu.json`（时间戳 + 三轴陀螺 + 三轴加速度）
- IMU 采样率要求 **250–400 Hz**

### 4. 采集动作要求（关键）

**必须移动相机本体，而不是动棋盘**（与 OpenCV 模式相反）。原因见「原理」。要求录满 60–90 秒，慢而不断，覆盖三轴平移 + 三轴转动 + 视场覆盖，且要过「检查数据」的量化门槛：

| 项目 | 通过要求 |
|------|---------|
| 录制时长 | ≥ 60 秒 |
| 码带解码成功率 | ≥ 90% |
| IMU 采样率 | 250–400 Hz |
| 陀螺仪激励 | 每轴峰峰值 ≥ 0.35 rad/s |
| 加速度激励 | 每轴峰峰值 ≥ 1.5 m/s² |
| 标定板双眼同时检测 | ≥ 60 帧 |
| 视场覆盖 | 3×3 网格中覆盖 ≥ 5 个区域 |

## 二、输出（Output）

录制产物落在 `sessions/<时间>/kalibr/`：

| 产物 | 含义 |
|---|---|
| `cam0.avi` | 左眼灰度视频（不含码带） |
| `cam1.avi` | 右眼灰度视频（不含码带） |
| `imu.json` | IMU 样本（时间戳、三轴陀螺、三轴加速度） |
| `capture.json` / `decoder_stats.json` / `dataset_manifest.json` / `integrity.json` | 录制元数据与完整性报告 |

Kalibr 求解（打 rosbag、相机/IMU 联合优化）由外部流程基于上述视频与 `imu.json` 完成，不在本工程内。

## 三、原理（Principle）

### 1. 核心思想：对齐「视觉位姿轨迹」和「IMU 积分轨迹」

Kalibr 的相机–IMU 标定基于**连续时间批量估计（continuous-time batch estimation）**，把整段轨迹用 B 样条（B-spline）参数化。要解的未知量是：

1. **相机与 IMU 之间的外参** `T_cam_imu`（刚性安装关系，旋转 R + 平移 t）
2. **两者之间的时间偏移** `t_offset`（相机曝光时刻 vs IMU 采样时刻的时钟差）
3. （可选）IMU 的噪声密度、随机游走等内参

两条观测链路观测的是**同一个刚体（相机本体 = IMU 安装体）的同一段运动**：

- **视觉链路**：每帧图像里检测 AprilTag 板，解出相机此刻的 6 自由度位姿 → 得到一条**相机位姿轨迹**（带真实物理尺度，因为 tag 边长已知）。
- **IMU 链路**：陀螺仪测角速度 ω、加速度计测比力 a，对时间积分 → 得到一条**IMU 的运动轨迹**。

它们之间只差一个固定的空间变换 `T_cam_imu` 和一个固定的时间平移 `t_offset`。Kalibr 就是让这两条轨迹在最小化残差的约束下**对齐**，从而解出 `T_cam_imu` 和时间偏移。

### 2. 为什么必须「动相机、动板则没用」

- IMU（陀螺仪 + 加速度计）测的是**它自己所在的相机本体的**角速度和比力。
- 如果相机静止、只动棋盘，IMU 读数几乎不变 → IMU 那条轨迹是空的 → `T_cam_imu` 不可观测，方程病态。
- 反过来，只有充分激励**平移**（加速度计才有信号）和**绕三轴转动**（陀螺仪三轴才有信号），每个自由度的外参才可解。这就是「运动要领」里把 90 秒拆成前后左右平移 + 绕 X/Y/Z 三轴转动的原因——**哪个轴不动，那个轴的外参就是病态的**。

### 3. 时间偏移为什么能解出来

视觉位姿和 IMU 积分在时间上错开 `t_offset` 时，把两条轨迹对齐后的残差会系统性变大；Kalibr 把 `t_offset` 也放进优化变量，通过整段数据的批量优化把它估计出来。这也是文档里强调「中途不要停顿」的原因——停顿会减少对齐所需的信息量。

### 4. 分两个阶段

（外部流程中的）Kalibr 求解分两步：

1. **先标相机**（`kalibr_calibrate_cameras`）：用 AprilTag 板求双目各自的内参/畸变和双目外参，产出 `camchain.yaml`。
2. **再联合标定**（`kalibr_calibrate_imu_camera`）：以第 1 步的相机链为初值，联合 IMU 数据解 `T_cam_imu` + 时间偏移，产出 `camchain-imucam.yaml`。

---

## 一句话总结

本工程负责录制「AprilTag 板 + 双目视频 + 码带解码出的 IMU 数据 + 充分激励的相机运动」，输出左/右目视频与 `imu.json`；后续 Kalibr 用连续时间批量估计把视觉位姿轨迹和 IMU 积分轨迹对齐，解出相机–IMU 外参与时间偏移（求解在外部进行）。
