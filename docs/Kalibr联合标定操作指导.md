# Kalibr 相机 + IMU 联合标定操作指导

> 适用：world intelligent 相机（4000×1200，左侧 160px 码带 + 内置 IMU）。
> 与 OpenCV Chessboard 模式用的是**两块不同的标定板**，见「前置条件」。

## 前置条件

1. **AprilTag 标定板**：8 列 × 6 行（`tagCols=8, tagRows=6`），每个 tag 边长 20 mm，间距为 tag 边长的 0.3 倍。**不是** OpenCV 模式用的 5×8 棋盘。
2. 相机**可移动/可转动**：IMU 在相机内部，必须移动相机本体才能激励 IMU（详见下节）。
3. 左右眼能同时完整看到标定板。

## 核心概念：为什么必须动相机，而不是动棋盘

OpenCV Chessboard 模式是「相机不动、动棋盘」。Kalibr 联合标定**相反**：

- 标定对象是**相机和内置 IMU 之间的外参（旋转 + 平移）以及时间偏移**。
- IMU（陀螺仪 + 加速度计）测的是它自己——也就是相机本体的角速度和比力。
- 如果只动棋盘、相机静止，IMU 读数几乎不变，Kalibr 无法求解 IMU 相关参数。

所以：**缓慢移动/转动相机本体（连带 IMU），让标定板始终保持在左右眼视野内。**

## 操作流程（3 步按钮）

1. 「开始录制」
2. 按下方「运动要领」持续移动相机 60–90 秒（录制中页面会抽稀显示 IMU 数据，辅助判断录制是否正常）
3. 「停止录制」→ 生成左/右目视频与 `imu.json`，交给外部 Kalibr 求解

## 运动要领

全程**缓慢、连续、不停顿**，标定板始终完整出现在左右眼：

| 时间 | 动作 | 激励目标 |
|------|------|---------|
| 0–15s | 相机缓慢前后、左右平移 | 加速度计（线加速度） |
| 15–30s | 绕 X 轴（俯仰，抬头低头）来回转 | 陀螺仪 X |
| 30–45s | 绕 Y 轴（偏航，左右转头）来回转 | 陀螺仪 Y |
| 45–60s | 绕 Z 轴（横滚，歪头）来回转 | 陀螺仪 Z |
| 60–90s | 三轴混合转动 + 平移，让标定板出现在画面上下左右及角落 | 视场覆盖 + 综合激励 |

要点：**慢而不断**。某个轴不转或转得太少，该轴标定就是病态的。

## 录制建议目标（供参考）

本工程已移除内置求解与「检查数据」步骤，录制质量由操作者结合页面抽稀 IMU 显示自行判断。建议尽量满足：

| 项目 | 建议目标 |
|------|---------|
| 录制时长 | ≥ 60 秒 |
| 码带解码成功率 | ≥ 90% |
| IMU 采样率 | 250–400 Hz |
| 陀螺仪激励 | 每个轴峰峰值 ≥ 0.35 rad/s |
| 加速度激励 | 每个轴峰峰值 ≥ 1.5 m/s² |
| 标定板双眼同时检测 | ≥ 60 帧 |
| 视场覆盖 | 3×3 网格中覆盖 ≥ 5 个区域 |

## 常见失败原因

- **拿错板**：用了 OpenCV 的棋盘而不是 AprilTag 板 → 「标定板检测」和「视场覆盖」不达标。
- **只动棋盘不动相机**：陀螺仪/加速度三个轴激励全部不足。
- **中途停顿/静止**：IMU 激励不足，时间偏移估计信息不足。
- **标定板出视野**：那几帧没有相机位姿，无法参与相机-IMU 对齐。

## 录制产物

停止录制后在 `sessions/<会话时间>/kalibr/` 下生成：

| 产物 | 说明 |
|---|---|
| `cam0.avi` | 左目灰度视频（1920×1200，不含码带） |
| `cam1.avi` | 右目灰度视频（1920×1200，不含码带） |
| `imu.json` | IMU 样本（时间戳、三轴陀螺、三轴加速度） |

后续 Kalibr 求解（打 rosbag、相机/IMU 联合优化）由外部流程完成，不在本工程内。
